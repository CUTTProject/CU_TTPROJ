Troubleshooting

Common problems and how to fix them.

Requests

403 with an empty response

Your token is missing, mistyped, or more than an hour old. Sign in again and use the new token. Check that the header reads Authorization: Bearer <token>, with a space after Bearer.

400: validation errors

A required field is missing or in the wrong format. The responseMessage names the field. Times use HH:mm and dates use YYYY-MM-DDTHH:mm:ss.

409: conflict

Something with the same unique value already exists. When registering, each school's admin email and address must be unique.

409: "Academic period … ended on …" or "… is archived"

The period is read-only, so it accepts no more uploads, edits or generations. Its data and timetable can still be read and downloaded. If you need to make changes, reopen it by extending its end date, or by setting its status back to ACTIVE. End dates are in UTC.

Uploads

Every row is skipped

  • Check the field names. CSV headers and JSON keys must match Data fields exactly, including capital letters.
  • Check the order. If lecturers fail with "No department has this code", upload departments first.
  • Save the file as CSV UTF-8. In Excel: File → Save As → CSV UTF-8.
  • Send it as a form field named exactly file (-F "file=@…").
  • Use the /bulk-upload address, not /bulk-upload/array.
  • Wrap your records in { "rows": [ … ] }. A bare array is rejected.
  • Send the Content-Type: application/json header.
  • Use the /bulk-upload/array address, not /bulk-upload.
  • For sections and enrollments, include "academicPeriodId" in the body.

Some rows are skipped

Look at errors in the response. Each entry gives the row, the field and the reason. For CSV, row is the spreadsheet row. For JSON, it's the position in rows, counting from 1. Fix those rows and send them again. Rows that were already saved are updated, not duplicated.

Generation

feasible: false

The scheduler ran out of time before removing every clash. Usually there are too many classes for the rooms and hours available. Try the following:

  • Add rooms, or check that roomCapacity values are correct.
  • Remove rooms or timeslot restrictions on sections that don't really need them.
  • Use split=yes or maybe on long sections. Shorter meetings are easier to fit.
  • Check that one lecturer isn't assigned more teaching hours than the week holds.
  • Run generation again. Each run explores differently, and a second run sometimes finds a clean solution.

A class was left out

The PDF and the GENERATED_TIMETABLE webhook list unplaced classes with a reason:

  • "No room large enough": the section's sectionEnrollmentSize is bigger than every allowed room. Add a larger room or loosen its rooms restriction.
  • "No free time and room could be found for it without a clash": its lecturer or students are busy at every time it could go. Loosen its restrictions, or split it.

A meeting that is longer than the school day, or than the time before or after the break, can never be placed. Shorten it or split it.

404: Unknown job

Job status is kept only while the server is running, and it may have restarted. Any timetable that was generated is still saved. Download the PDF to see it.

Generation takes longer than expected

Large schools can take several minutes. The scheduler stops as soon as it finds a clash-free timetable, or when its time limit is reached, whichever comes first. If no timetable has appeared after about 10 minutes, generate again.

Webhooks

Nothing arrives

  • Run the test endpoint. It reports what your server replied.
  • The address must be https and reachable from the public internet.
  • Check that the webhook is enabled: GET /api/schools/webhook.

Signatures never match

Sign the raw body exactly as received. Many web frameworks parse JSON before your code runs, and turning it back into text changes the spacing. Also check you're using the most recent secret.
