Generating a timetable

Create an academic period, add its classes, then let the scheduler work.

1. Create an academic period

A period is one semester or term. Each period has its own sections, enrollments and timetable.

curl -X POST $BASE/api/academic-periods/create \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "academicPeriodName": "2026/2027 First Semester",
    "academicPeriodSession": "2026/2027",
    "academicPeriodSemester": "FIRST",
    "academicPeriodStartDate": "2026-09-14T00:00:00",
    "academicPeriodEndDate": "2027-01-29T00:00:00"
  }'

Keep the id from the response. You'll need it for every step below:

export PERIOD=3f2b...   # data.academicPeriod.id

When a period ends

Each period shows an academicPeriodPhase, worked out from its dates:

PhaseWhenCan you change it?
UPCOMINGBefore the start dateYes. Set it up ahead of time.
IN_PROGRESSBetween the start and end datesYes
ENDEDFrom the end date onwardsNo, it's read-only
ARCHIVEDYou set its status to INACTIVENo, it's read-only

A period ends at the exact date and time in academicPeriodEndDate, in UTC. A read-only period no longer accepts section or enrollment uploads (including dry runs), edits, or new generations. You can still read its data and download its timetable at any time.

The end date must be after the start date.

To reopen a period, update it: extend its end date, or set an archived period back to ACTIVE.

curl -X PUT $BASE/api/academic-periods/update \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "id": "'$PERIOD'", "academicPeriodEndDate": "2027-02-12T00:00:00" }'

To archive a period early, send "academicPeriodStatus": "INACTIVE" instead. To list only some periods, filter by phase: GET /api/academic-periods/read?academicPeriodPhase=IN_PROGRESS.

2. Upload sections and enrollments

A section is one group taking a course: who teaches it, how many students, and how many minutes a week it runs. Enrollments say which students are in which section. This is what the scheduler uses to stop two of a student's classes landing at the same time.

curl -X POST "$BASE/api/sections/bulk-upload?academicPeriodId=$PERIOD" \
  -H "Authorization: Bearer $TOKEN" -F "file=@sections.csv"

curl -X POST "$BASE/api/enrollments/bulk-upload?academicPeriodId=$PERIOD" \
  -H "Authorization: Bearer $TOKEN" -F "file=@enrollments.csv"

The period id goes in the body, next to rows:

curl -X POST $BASE/api/sections/bulk-upload/array \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{
    "academicPeriodId": "'$PERIOD'",
    "rows": [
      { "courseCode": "CSC 101", "sectionName": "CSC 101-CSC", "sectionEnrollmentSize": 55,
        "lecturerStaffNumbers": "L001", "sectionDurationMinutes": 180,
        "eventType": "LAB", "split": "yes" }
    ]
  }'

curl -X POST $BASE/api/enrollments/bulk-upload/array \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{
    "academicPeriodId": "'$PERIOD'",
    "rows": [
      { "studentMatriculationNumber": "SCHOOL/2024/CSC/0001",
        "courseCode": "CSC 101", "sectionName": "CSC 101-CSC" }
    ]
  }'

See Sections for splitting a course into several meetings, teaching two sections together, and fixing a class to a room or time.

3. Start generation

curl -X POST "$BASE/api/time-table/generate?academicPeriodId=$PERIOD" \
  -H "Authorization: Bearer $TOKEN"

This returns straight away. The scheduler keeps working in the background:

{
  "responseCode": "202 ACCEPTED",
  "responseMessage": "Generation queued. No webhook is configured, so poll the status url.",
  "data": {
    "jobId": "a71c...",
    "status": "QUEUED",
    "statusUrl": "/api/time-table/generate/a71c..."
  }
}

4. Wait for it to finish

Generation takes up to a few minutes, depending on the size of your school. There are two ways to find out when it's done:

  • Check the status: call the statusUrl every 15–30 seconds.
  • Get notified: set up a webhook and the finished timetable is sent to your system automatically.
curl $BASE/api/time-table/generate/a71c... -H "Authorization: Bearer $TOKEN"
statusMeaning
QUEUEDWaiting to start.
RUNNINGBuilding the timetable.
SUCCEEDEDFinished. Check feasible below.
FAILEDNo timetable was produced. failureMessage says why.

5. Read the result

When the status is SUCCEEDED, check these fields:

FieldMeaning
feasible: trueEvery class was placed with no clashes. You're done.
feasible: falseThe scheduler ran out of time with some clashes left. See Not feasible.
scheduledEvents / totalEventsHow many class meetings were given a time, out of how many there are.
stopReasonFEASIBLE_SOLUTION_FOUND, TIME_LIMIT_REACHED, or NOTHING_TO_SOLVE (no sections, rooms or times to work with).

6. Download the timetable

curl "$BASE/api/time-table/download/pdf?academicPeriodId=$PERIOD" \
  -H "Authorization: Bearer $TOKEN" -o timetable.pdf

The PDF lists every class by day, with its time, room and lecturer. It also lists any class that couldn't be placed, and why.

The timetable is saved, so you can download it again at any time without generating it again. Generating again replaces it.

Optional: see what clashes with what

The conflict graph shows which sections can never run at the same time, because they share a lecturer or students. Download it and paste it into Graphviz Online to view it.

curl "$BASE/api/time-table/conflict-graph/download?academicPeriodId=$PERIOD" \
  -H "Authorization: Bearer $TOKEN" -o conflict-graph.dot
