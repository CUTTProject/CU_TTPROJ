Uploading your data

Send your school's data as CSV files or as JSON, one type at a time, in a set order.

CSV or JSON?

Both do exactly the same thing: same checks, same report, same results. Choose whichever suits you:

  • CSV: export a sheet from Excel or Google Sheets and upload the file. Best for setting up by hand.
  • JSON: send the rows in the request body. Best when your student records or HR system sends the data automatically.

The field names are identical: a CSV column called departmentCode is a JSON key called departmentCode. You can also mix formats, for example CSV for rooms and JSON for students.

The order

Each file refers to things uploaded before it. For example, a lecturer row names a department, so departments have to exist first. Upload in this order:

#DataEndpointNeeds
1Departments/api/departments—
2Lecturers/api/lecturersDepartments
3Rooms/api/rooms—
4Programmes/api/programsDepartments
5Courses/api/coursesDepartments
6Curriculum/api/program-coursesProgrammes, courses
7Students/api/studentsProgrammes
8Academic periodCreate one—
9Sections/api/sectionsCourses, lecturers, rooms, period
10Enrollments/api/enrollmentsStudents, sections

Add /bulk-upload to the endpoint for a CSV file, or /bulk-upload/array for JSON. For example, /api/departments/bulk-upload or /api/departments/bulk-upload/array.

Steps 1–7 describe your school and rarely change. Steps 9–10 are uploaded for each academic period, since the classes on offer change every semester.

Programmes and curriculum are optional if your school doesn't use them. In that case, give each student a departmentCode instead of a programCode.

Sending data

Send the file as a form upload named file. The first row must be the column names.

curl -X POST $BASE/api/departments/bulk-upload \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@departments.csv"

where departments.csv contains:

departmentCode,departmentName
CSC,Computer Science
SEN,Software Engineering

Send a rows array. Each row is an object whose keys are the column names.

curl -X POST $BASE/api/departments/bulk-upload/array \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "rows": [
      { "departmentCode": "CSC", "departmentName": "Computer Science" },
      { "departmentCode": "SEN", "departmentName": "Software Engineering" }
    ]
  }'

Leave out keys you don't need. Numbers such as roomCapacity can be sent as JSON numbers.

Sections and enrollments

These two belong to an academic period, so they also need its id:

Pass the period in the address:

curl -X POST "$BASE/api/sections/bulk-upload?academicPeriodId=$PERIOD" \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@sections.csv"

Pass the period in the body, next to rows:

curl -X POST $BASE/api/sections/bulk-upload/array \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "academicPeriodId": "3f2b...",
    "rows": [
      { "courseCode": "CSC 101", "sectionName": "CSC 101-CSC",
        "lecturerStaffNumbers": "L001", "sectionDurationMinutes": 180,
        "eventType": "LAB", "split": "yes" }
    ]
  }'

Check before you save

Add ?dryRun=true to the address to check your data without saving anything. You get the same report a real upload would give. This works for both CSV and JSON.

curl -X POST "$BASE/api/lecturers/bulk-upload?dryRun=true" \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@lecturers.csv"
curl -X POST "$BASE/api/lecturers/bulk-upload/array?dryRun=true" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "rows": [ { "lecturerStaffNumber": "L001", "departmentCode": "CSC" } ] }'

Reading the result

Every upload, CSV or JSON, returns a report like this:

{
  "data": {
    "dataset": "LECTURERS",
    "dryRun": false,
    "submitted": 55,
    "created": 53,
    "updated": 0,
    "unchanged": 0,
    "skipped": 2,
    "errors": [
      { "row": 14, "column": "departmentCode", "value": "CSCC",
        "message": "No department has this code" }
    ],
    "warnings": []
  }
}
  • Good rows are saved even if others fail. Fix the rows listed in errors and upload the file again.
  • row tells you which row has the problem:
    • CSV: the spreadsheet row number. The header is row 1, so the first data row is row 2.
    • JSON: the position in rows, counting from 1.
  • warnings are rows that were saved but had a value ignored, such as a department head who doesn't exist yet.

Uploading again is safe

Each row is matched to what's already there by its code, such as departmentCode, lecturerStaffNumber or studentMatriculationNumber. Matching rows are updated, not duplicated. To correct your data, fix it at the source and send it again. That also makes it safe for an automated JSON sync to send the full list every night.

Department heads: leave departmentHeadStaffNumber blank on your first departments upload, because lecturers don't exist yet. Fill it in and upload departments again after uploading lecturers.

Uploading a section again replaces its lecturers, rooms and time restrictions with what's in the new file.
